# Project rules

- Investment Managers administration uses the existing authenticated asset-manager API; valuation features remain isolated from policy conversions, allocations and approval calculations.
- Keep funds nested under their asset manager and edit by stable IDs; matching fund names across managers must remain independent.
- Save the wizard's final-review and portfolio display snapshots inside the existing policy form and render them with shared review content in approvals; intact submitted sections are authoritative, and legacy portfolio fallback uses only saved fund names, percentages and net investment, never current fees/catalogue or gross investment.
- Client policy portfolio display uses the same submitted-section reader as approvals, without catalogue lookups; draft resume restores the original investment input and manager names travel with selected funds so reopening cannot deduct charges twice or lose manager identity.
- Fund valuations use Mongo Decimal128 plus append-only revision history and a unique fund/date index; corrections use revision-checked atomic updates, and future unit purchases must pin valuation ID, revision and applied price rather than dereference a mutable latest price.
- Investment funding authorisation stays isolated in backend/fundingAccess.cjs; it must never widen requireRootOrgAccess, approvals or fund management.
- Future investment view/request/transaction guards live in backend/investmentAccess.cjs, resolve roles/organisations from the database and reuse requireRootOrgAccess plus approved/active client-policy lookup; separate frontend hints require server-authorised policy access so new investment permissions cannot grant access to unrelated workflows or policies.
- Funds Received confirmation lives in backend/fundingConfirmation.cjs and writes only the PolicyFunding collection (unique per policy, append-only history) and the audit log, never policies/allocations/activation; any future reversal must require a reason, add to the history and bump the revision rather than delete or overwrite. Gross shown for funding is the submitted investmentAmount only when the saved deductions reconcile to the saved net; otherwise it is flagged, never derived.
- Initial investment validation stays in the unregistered, read-only backend/investmentPreview.cjs module, using decimal arithmetic and exact submitted amounts with trusted fund-ID ownership; incomplete or contradictory snapshots block validation rather than recalculating allocations, so Excel checks cannot enable transactions or mutate approved policies.
